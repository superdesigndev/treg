# The MiniMax plugin

The MiniMax Plugin Marketplace serves MiniMax Code (desktop) and MiniMax Agent (cloud). The treg
plugin there is **skills-only**: MiniMax rejects any package holding a credential and admits an
authenticated MCP only through its App/Connector program (see "Later: an App").

Source of the rules: MiniMax's *Plugin Development and Submission Guide* (Feishu wiki
`QlTLwbAGNiACwLkWI85cFxHzn4L`, behind a Feishu login). The machine-checkable rules (manifest shape,
category list, path, file and size limits, no credentials) are encoded in
`scripts/minimax_plugin.py`, which `tests/test_plugin.py` runs.

`plugins/minimax/` is the plugin root, with `.minimax-plugin/plugin.json` directly inside it, as
MiniMax requires of a ZIP root or a GitHub subdirectory. The skill is generated by
`scripts/build_plugin.py` (the served page unchanged, no bootstrap) and exposed at runtime as
`treg:treg`. Build a submission ZIP with `python3 scripts/minimax_plugin.py --zip OUT.zip`.

Rules the validator cannot check:

- `version` must bump whenever package content changes (region or target-only changes may keep
  it); ours tracks `pyproject.toml`.
- `exampleQueries` must be production content, and the skill body executable instructions, not
  marketing.
- The description says what problem the plugin solves, not how.
- The manifest carries no `license` key: their schema defines none and unknown keys risk the
  validator. `SKILL.md` ships under the repo's Apache-2.0.

Submission goes through MiniMax's Feishu form with GitHub as the source (subdirectory
`plugins/minimax`, a `main` or release-tag ref). An update keeps `name` `treg`, bumps `version` and
resubmits with the new ref. The operational runbook lives in the private repository.

## Known review risks

1. **`curl ... | sh` in the skill.** The package holds no install script, but the skill tells the
   agent to run one. If a reviewer objects, add a MiniMax bootstrap in `scripts/build_plugin.py`
   pointing at `uv tool install tools-registry` (the CLI on PyPI).
2. **Cloud target.** On MiniMax Agent the skill works only if the sandbox has a shell with network
   egress and can complete `treg login`. Dropping the cloud target is catalog metadata, not a
   version bump.

## Later: an App

Native MCP tools in MiniMax need their App/Connector track: contact MiniMax before building, give
them test and prod Streamable-HTTP MCP endpoints and an OAuth issuer (DCR, PKCE S256, refresh,
revocation); they assign a `provider` and the plugin gains `treg.app.json`
(`{"schemaVersion":1,"provider":"treg"}`). treg's OAuth server in front of `/mcp/`
([mcp-oauth](context/architecture/mcp-oauth.md)) already covers the server side.
