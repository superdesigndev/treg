# Endpoint catalog - platform-grouped operations per provider

The OAuth registry (`oauth_providers.py`) says how to connect a provider; the catalog says what a
connected key can DO: which endpoints exist, what they cost and what they return. It adds three
axes:

- **platform** (tiktok, instagram, web, ...): the marketplace grouping, the system the data is about.
- **capability** (`tiktok.user.profile`): the same job across providers, the join key for
  comparison and for routed endpoints.
- **verified example responses**: captured live, because choosing an API comes down to what
  actually comes back.

Data files are YAML under `src/treg/catalog/`, loaded through `catalog_store`. The open JSON
handlers live in `routers.catalog`; `api.py` attaches that router before the `/catalog/{slug}` page
route so the specific Catalog API paths keep precedence. `<service>.extended.yaml` files are
generated by `scripts/catalog_ingest.py` and never hand-edited; `examples/<endpoint-id>.json` are
truncated, scrubbed live responses.

## Two tiers

| | `tier: core` - `<service>.yaml` | `tier: extended` - `<service>.extended.yaml` |
|---|---|---|
| written by | a human, one endpoint at a time | `scripts/catalog_ingest.py`, from the provider's spec |
| `capability` | required | normally absent |
| `input` / `test_request` | hand-written | generated where the provider documents parameters with example values |
| example size | about 10 KB, arrays to 2 items | about 2 KB, arrays to 1 item (shape, not fidelity) |

Both files load under one provider, the core file first: its header facts (`limits`, `pricing_url`,
`source.docs`, `cache`, `ceiling_param`, `queryParams`) win over the extended file's, and an id
declared in both resolves to the core row. `catalog_ingest.py` drops any `(method, path)` the core
file already curates, so an endpoint appears once. Promoting an extended entry means moving it into
the core file and completing it; hand edits to an extended file are lost on the next ingest.

**An ingested price is a claim we will charge on, so a generated `free` is a bug, not a default.**
The proxy skips a `free` block (its `usd` is falsy) and bills the provider fallback, so a wrongly
generated `free` publishes $0 while the balance moves. For an `oauth_billed` provider
([auth-secrets](auth-secrets.md)) the generator must price every route, and a test asserts the
published price equals the reserved one. Where a provider publishes a row per ACTION, transcribe the
card (`catalog_ingest.X_RATES` is the card, `X_ROUTE_RATES` the route mapping, each note naming its
row); a judgement-call mapping says `confidence: inferred` and takes the dearer reading, because
treg pays the difference. A rate that applies only when the caller owns the developer app applies
to treg on a registry connect, not to our members.

OpenRouter video models all use `POST /videos`, so `core_body_models` dedups on the fixed
`body.model` values core curates rather than on path. The OpenRouter and Replicate generation
ingesters emit no capability guesses and set `domain: models`;
`carry_verification(..., carry_capability=False)` keeps verification evidence and reviewed
names/kinds without resurrecting inferred capability tags. Both ingesters are deterministic.

Generation models are not interchangeable, so core AIGC rows carry PER-MODEL capabilities
(`video-gen.hailuo.from_text`) and the job-level `video-gen.from_text` family is deliberately
memberless, reserved for hand-picked models (capabilities.yaml header). Routes to one model (direct,
reseller, OpenRouter, Replicate) share the per-model key and sit on one comparison row.

## Schema

### capabilities.yaml

- A capability id is dot-delimited, lowercase; the FIRST segment is its platform slug. Ids name the
  *job*, not the provider's operation.
- Provider files may carry `proposed_capabilities:` for a job the taxonomy lacks. A proposal is live
  the moment it loads (first file by name wins the description), so the validator keeps it a
  staging area: an endpoint may use a global or own-file proposal; repeating a global id, or one id
  proposed with different descriptions, is an error; a proposal used by two providers is a warning
  to promote it.
- `capability_titles:` gives a long description a short shelf title. Title and description are both
  indexed by shelf filter, search and find; a title naming no capability fails the load.
- One job, one id: two ids of one platform with the same description are a warning, because they
  split one comparison row. Renaming means checking `contracts.yaml` and `adapters.yaml`, which are
  keyed by capability.
- Under the `AI generation` category, platform means the generated-media modality. Text-to-video and
  image-to-video stay separate because their inputs and prices differ.

### `<service>.yaml`

```yaml
provider: tikhub                # must equal OAuthProvider.service
source: {docs: https://docs.tikhub.io/, openapi: https://api.tikhub.io/openapi.json, curated: 2026-07-28}
limits: "10 requests/second per key"   # optional: the rate/quota model in one line
pricing_url: https://...               # optional: where CURRENT prices live
endpoints:
  - id: tikhub.tiktok.user.profile   # unique across the whole catalog; convention <provider>.<capability>
    capability: tiktok.user.profile
    platform: tiktok                 # must equal the capability's first segment
    domain: user                     # optional section; derived when absent (see "Domain sections")
    scope: any_account               # any_account (scrapers) | own_account (first-party OAuth)
    kind: data                       # optional; data (default) | action | account | utility
    method: GET
    path: /api/v1/tiktok/web/fetch_user_profile
    name: "TikTok user profile by username - followers, bio, stats"   # ours, <= 60 chars
    summary: "Public TikTok profile by username"   # the provider's text, verbatim
    input:
      queryArrayEncoding: json      # optional: json | comma | repeated (default)
      queryParams:
        uniqueId: {type: string, required: false, note: "username from the profile URL", example: "tiktok"}
      note: "one of uniqueId | secUid"
      # also pathParams, headers, body, bodyType (json|form|multipart). Unknown keys fail the load.
    test_request: {queryParams: {uniqueId: "tiktok"}}   # EXACT params the verifier sends; must be cheap
    expect: {json_path: code, equals: 200, misses: [404]}   # optional; default is HTTP 2xx
    cost: {type: per_success, value: 0.0015, currency: USD, note: "charged on 2xx only"}
    verified: 2026-07-28             # last PASSING verify run; absent = unverified
    added: '2026-07-28'              # REQUIRED: UTC day this tool reached main
    example_response: examples/tikhub.tiktok.user.profile.json
    note: "..."                      # optional: a caller-facing caveat about the whole tool or its answer
```

Every `note` is caller-facing. A caveat goes to its most specific home: a parameter's `input.*.note`,
then the charge's `cost.note`, then the row's `note`. Only the endpoint's own detail
(`GET /catalog/endpoints/{id}`, `treg catalog get`, `/mcp/` `catalog_get`, the dashboard drawer) shows
the row's `note`; lists, search and sibling rows leave it out. Maintainer context goes in a YAML
comment, evidence in the PR body.

The strict models ([catalog-schema](catalog-schema.md)), shared by the loader and the validator,
refuse any `input` key and any parameter-spec key outside their vocabulary, because a misspelt
location or an unquoted note with a comma is otherwise silently dropped.

### `added` - the day a tool reached main

Every row, core and extended, carries `added: 'YYYY-MM-DD'`: the **UTC** day the tool first became
available on main. It lives on the row, never in a shared dates file every listing PR would
conflict on. It is not `verified` and not `source.curated`.

- An existing tool keeps its day; a new tool takes the day its PR is prepared, and the author
  updates it if the PR waits long.
- **Never changes**, keyed by id across the catalog, so a promoted or moved row keeps it. The
  `Catalog added dates` workflow runs `scripts/catalog_added.py --base origin/<base>` and fails on
  any changed date unless the PR carries the `added-date-change` label (`--allow-change` locally).
- `scripts/catalog_added.py` writes today's UTC date into rows without one (text insertion, so
  comments survive); `--check` lists them. `catalog_validate.py` fails a missing, malformed or future
  date.
- `carry_verification` carries `added` by id from every catalog file BEFORE its method/path check,
  so a moved route keeps its date and only a never-seen id gets today. For a route that still
  matches it also carries `cost` (under a freshly generated `cost.note`), `observed_cost`, `expect`, `untestable`, `status` and a reviewer's
  row `note` (no ingest writes one), and from a
  row in the v2 spelling its `reserve`, `settle`, `bill`, `error`, `miss` and `not_found`, and a
  priced row's `price` together with its `provenance` (an absent one stays absent and inherits the
  provider's default), but not `platform_blocked` once the fresh row declares `resource_ownership.requires`.
- `scripts/catalog_backfill_added.py` dated existing rows once from main's first-parent history;
  reviewed renames are applied with `--same-tool OLD=NEW`.

#### Recently added tools - two search options

`added_within_days=N` and `sort=newest` are the same options on `GET /catalog/search`, `treg catalog
search --new [DAYS] --sort newest` and MCP `catalog_search` on both `/mcp/` and `/mcp/v2/`. Without
them search is unchanged apart from `added` on each row. `store.added_options` refuses a window below
one day (400; `invalid_option` on MCP) and caps above `ADDED_DAYS_MAX`, saying so in
`capped_at_days`. With an option, `application.catalog_search.added_page` returns a flat list (words
optional; newest first with `sort=newest` or no words), runs no judge and writes no experiment
record. A routed row has `added: null` and is excluded (it is a choice among tools, not a tool); a
listed hub tool's `added` is its approval day (`HubListing.decided_at`).

### Domain sections - grouping endpoints for browse

`catalog_store._domain` derives `domain:` (capability middle segment, else a path keyword, else the
path's grouping segment, else `other`) by splitting into whole words and matching
`DOMAIN_KEYWORDS`: a short key (`ads`, `llm`) must match a whole word, a stem key (`keyword`,
`backlink`) matches by prefix, so `ads` never matches inside `leads`. `DOMAIN_NOISE` drops
brand-family and delivery-version path segments. A heading that comes from a capability's middle
segment cannot be filtered there; renaming it is a `capabilities.yaml` taxonomy edit.

### Kind - the browse surface vs. the plumbing

| `kind` | what it is | browse |
|---|---|---|
| `data` (default) | fetch / scrape / enrich a resource | shown |
| `action` | a meaningful WRITE on the connected user's own account | shown |
| `account` | the provider's own list/webhook/saved-search/credit CRUD | hidden |
| `utility` | helpers with no data of their own (signers, enum listings, task polls) | hidden |

The platform census (`GET /catalog/platforms`) counts data + action only. `GET
/catalog/platforms/<slug>` returns only the browse surface plus `hidden_count`; `?include_hidden=1`
returns everything with `kind` on each row. `kind` is a reviewed judgement that `carry_verification`
re-attaches by id, so re-ingesting must not reset it to `data`.

### Naming - `name` is the search surface we own

`summary` is the provider's text, verbatim; `name` is ours and searched at the same weight. The
formula: **job + the input the caller must hold + top output facets**, at most 60 characters, and it
must read as a natural title.

1. Name the JOB in task words, never the vendor's operation title or version codes.
2. Say the INPUT ("by domain", "by LinkedIn URL"): agents search by what they hold.
3. Say the top OUTPUTS when people search by them ("headcount", "reviews").
4. One concept, one word, catalog-wide ("postings", never sometimes "vacancies").
5. Prefer the longer word form: matching is prefix-based and never works backward.
6. No dead words: "API", "data", "get", "fetch", "endpoint".
7. No stuffing. Overflow vocabulary belongs in the capability description or `aliases.yaml`.
8. TRUTH over vocabulary: derive the name only from the row's own summary, path and inputs. A name
   claiming an output the endpoint does not return is a lie an agent will spend money on.

### `<service>.extended.yaml`

Generated; re-run `uv run python scripts/catalog_ingest.py <service>` instead of editing. Ids are
`<service>.x.<path-slug>`, keeping them out of the `<provider>.<capability>` namespace. Required:
`id`, `platform` (must exist in `capabilities.yaml`), `method`, `path`, `summary`. `capability`,
`cost`, `input` and `test_request` are optional; a reviewed `capability` in an extended file is held
to the full core rules, and AIGC generation coverage forbids inferred mappings entirely.

- `verified` + `example_response` carry the same weight as in core: verified implies a
  `test_request` and an existing example file.
- An entry that has been through the pipeline (it has a `test_request` or a state key) must claim
  exactly one non-empty state, which the validator enforces:
  - `untestable: <reason>` - set at ingest: no test request is possible with a bare key.
  - `unverified: http 404 ...` - set at verify: the call was made and failed. A finding: `402`
    means a paid plan tier, a family-wide run of `404`s means the provider's scraper is broken.
  - `skipped: <reason>` - set at verify: the call was affordable but deliberately not made. The
    reason names the sibling that WAS verified, or why one call costs too much. These clear with a
    top-up and re-run; the other two need a human.
- `host: <fqdn>` marks an endpoint relative to another API root. It is executable only when
  `OAuthProvider.catalog_targets` maps that exact hostname to a safe HTTPS base URL (and optional
  credential-profile override); `profile_for_catalog_host` rejects malformed, credential-, port-,
  query- or fragment-bearing targets before reserve. The catalog alone can never authorize a host.
- `scope_gap: <one line>` says treg's OAuth app lacks a scope for this route. These stay listed on
  purpose: the set of gaps answers "which scopes should the app request". Expect 403 until widened.

Query arrays: `input.queryArrayEncoding` sets one wire format for every array parameter of an
endpoint. `catalog_store.query_values()` is shared by MCP request assembly and `call_template()`, so
the schema and the paste-ready command cannot disagree. Nested JSON bodies use dotted keys
(`params.domain`); `call_template()` unflattens them, while query names that literally contain a
dot (`user.fields`) stay as written.

## Cost - the file keeps the billing unit, the server computes USD

A `cost` block stays in the unit the PROVIDER bills in, because that number stays correct when a
rate moves. `Catalog.cost_view` adds `usd` at serve time from `fx.yaml`, so a rate refresh re-prices
the catalog without touching provider files. Clients lead with `usd` and fall back to the native
amount when it is null. A row in the v2 spelling writes `price`, `provenance`, `reserve`, `settle`
and `bill` instead and serves a `cost` derived from them ([catalog-schema](catalog-schema.md)), so
what follows about reading `cost` holds for it; how it bills is
[money](money.md#rows-in-the-v2-spelling).

```yaml
cost:
  type: per_result        # per_call | per_result | per_success | free | quota_rows
  value: 2.00             # non-null unless confidence: unknown
  currency: USD           # USD | CNY | credit | unit
  per: 1000               # the quantity `value` covers (default 1)
  unit: row               # what `per` counts, or under `currency: unit`, the provider's meter
  source: docs            # rate_card_api | docs | observed | vendor_email | inferred
  source_url: https://...
  checked: 2026-07-28     # when the PRICE was confirmed
  confidence: documented  # verified | documented | inferred | unknown
  note: "..."             # the half of the charge the schema cannot hold
```

Read a block as "`value` `currency` per `per` `unit`"; `cost_view` divides, so a CPM of
`value: 2.00, per: 1000` serves `usd: 0.002` per row. `type` on table rows is the billing rule (a
failed `per_success` generation is not charged), not the display unit.

**Three denominations convert differently.** A real currency uses `fx.yaml` `rates_to_usd`.
`currency: credit` is provider-scoped (one provider's credit has nothing to do with another's), so
it converts with `credit_rates_usd[<provider>]`, which is why `cost_view(cost, provider)` takes the
provider. `currency: unit` is a provider meter (Semrush API units, Majestic's independent
allowances) priced by `unit_rates_usd[provider][unit]`, one row per meter.

Each `credit_rates_usd` / `unit_rates_usd` entry carries `usd` plus `basis`/`source`/`checked`: the
cheapest PUBLICLY listed tier, so the figure is an upper bound on real spend. `usd: null` is
deliberate (no published per-credit price, or an own-key-only provider treg holds no rate for):
those endpoints keep `cost.usd = null` and display natively, because a guessed dollar figure is
worse than an honest credit count. A v2 price in credits or a meter needs an entry, a null one
included; a missing entry fails validation. Both blocks must stay
ABOVE `rates_to_usd:` - `catalog_fx_update.py` rewrites the file from the text before that key and
discards everything below it.

Two treg-set kinds exist for providers with no per-call vendor price; [money](money.md) owns the
billing side:

- **`kind: treg_shared_plan`**: a rate treg sets on a flat-fee subscription. The basis must start
  with "treg shared-plan rate", name the vendor fee and the break-even volume, and `fee_usd_month`
  must be present (`check_fx`). Reviewed monthly against `reconcile.shared_plan_recovery`.
- **`kind: treg_trial`**: exactly $0 with `trial_calls_per_team_day` beside it, served on treg's
  free-tier key. At zero the price gives no brake, so the allowance is the congestion control
  (`_enforce_trial_allowance`, per team per UTC day, successful platform calls with a non-free
  catalog cost only, fail-closed). `cost_view` attaches the allowance to every $0 it serves. The
  validator refuses a non-zero trial and a zero with no allowance.

### Price tables

Finite AIGC matrices, linear rates and usage-settled generation replace `value` with an ordered
first-match `table` plus an explicit `fallback`:

```yaml
cost:
  type: per_success
  table:
    - {when: {body.model: Model-A, body.resolution: 512P, body.duration: 6}, value: 0.3}
    - {when: {body.model: Model-B, body.resolution: 768P}, value: 0.13, times: body.duration}
  fallback: {value: 2.0, note: "most expensive supported combination"}
  currency: USD
  settle: table                 # or usage
  # usage: {path: usage.cost, unit: usd}
```

- `when` is a subset match after input defaults, on location-qualified paths (`body.model`,
  `queryParams.mode`) so query/body collisions cannot price the wrong field. Every `when` field must
  be required or have a `default`; narrow rows precede broad ones; the validator rejects shadowed or
  duplicate conditions, unknown keys, non-finite values, values outside the input's enum/min/max, and
  `value` together with `table`.
- `times` multiplies by one numeric field with a positive `max`. A value outside the declared range,
  non-finite or non-positive (whatever minimum the field declares) matches no row and prices at the
  fallback, so a request can neither reserve zero nor bill past the ceiling. A sentinel such as
  `-1` is priced by a flat row that pins it, and that row is left out of the advertised rate span.
- `fallback` is a hand-written global upper bound, checked against every row's maximum.
- `settle: table` reserves and settles the matched row. `settle: usage` reserves the matched row as
  an estimate and settles the reply's `usage.path` figure, which may exceed the reserve; a flat
  `value` may also declare `settle: usage` with its `fallback` as the reserve. `usage.unit` is `usd`,
  `credit` (when fx.yaml prices that provider's credit) or a native meter with a
  `unit_rates_usd[provider][unit]` entry. `usage.terms` (unit `usd`) sums several meters times
  positive USD rates; a term path may select a list item by key
  (`candidatesTokensDetails[modality=IMAGE].tokenCount`); an absent meter counts as zero (proto3
  JSON omits zeros) and a response with none settles at the reserve. Settlement itself is in
  [money](money.md).
- Display: `_table_floor` computes the cheapest row into `cost.table_min`, served as `usd_min`
  beside `usd` (still the ceiling reserve and eligibility read), so every surface shows `$low-$high`.
  A table whose every row multiplies by a recognized meter field (`duration` in seconds, `max_steps`
  in steps) is also quoted as a unit rate (`rate_usd_min`, `rate_usd`, `rate_unit`).

### Request- and response-derived billing declarations

- **`reported_charge: {path, unit: usd | credit}`** on a paid synchronous cost: the estimate still
  reserves a safe ceiling; a finite nonnegative response value settles exactly; a missing value in a
  body whose own `status` is 400 or more settles at zero; other missing or invalid evidence falls
  back to the normal estimate/miss rules. It cannot be combined with `cost.settle`.
- **Charge headers** (`settle._CREDIT_HEADERS`) name each provider's header and its sign; one
  provider reports a debit as a negative number, so the multiplier is explicit rather than "any
  negative number is a charge". A header absent on a free route or failed request settles as
  unreported, not zero.
- **`cost.modifiers`**: each rule names a parameter location (`query`, `body`, `lookups`), a match
  (`truthy`, `present`) and exactly one credit effect (free, fixed credits, or credits per requested
  result). `reserve_only: true` keeps a documented rider that repeat live balance evidence shows is
  not billed in the hold only; `settle: modifiers` then charges only the measured modifiers, and
  `settle: base` settles at the base when evidence shows riders are neither billed nor delivered. A
  price below the documented one needs repeat live balance evidence when the provider reports no
  per-call charge.
- **`cost.reserve`** says how a `per_result` hold is sized, because the unit cannot (a `keyword` may
  be asked about or returned). `{entities: {}}` holds per entity the request names; `{rows: {param,
  default: {value, source}, max}}` holds the caller's declared integer field, else the sourced
  default, clamped and rounded up to whole `per` blocks. `cost.settle: {count: {path}}` settles the
  response list's length capped at the hold. A `per_result` cost in an entity unit
  (`resolve._ENTITY_UNITS`) must declare `reserve`; `catalog_validate.UNDECLARED_RESERVE` lists the
  rows that still infer it, and only shrinks.
- **`cost.quantity: {field, max, applied?}`** prices a call by a whole number the caller chooses (a
  budget of provider credits). Out of range is a 400 before reserve; the hold is `quantity x price`
  and `settle: quantity` settles exactly that, ignoring provider-reported charges (often 0 for added
  room). When `applied` is present and not `true` (the provider recognised a repeated purchase id)
  the call settles at 0. A cancel after the request left (`settle._finish_cancelled_call` with
  `sent`) charges the hold, because the units may already be added; the retry with the same purchase
  id then settles at 0. Required on a `per_success` price with no `reported_charge`.
- **Terminal presence**: an async single-record `per_success` row with no per-job charge may use
  `settle: terminal_presence` with `presence: {row: data.0, field: email}` or `{field: number}`. An
  absent or empty field settles zero, a nonempty one the held price, a missing or malformed result
  the reserve. Validation requires `body_allowlist` and a one-item input array or scalar inputs, so a
  shared key cannot buy several results under one hold.
- **`cost.display`** flags (`unit`, `grouped`, `round_up`, `variable`, `value`, `maximum`) change only
  the advertised figure (`Catalog.advertised_usd`, `usd_per_call` in search and get); `usd` and
  settlement are untouched. A grouped price needs a positive integer `per`; a table display must
  describe its maximum.
- A scalar `unit: character` is request-priced: `_body_text_characters` counts the top-level JSON
  `text` string; invalid or empty input reserves one character, never zero.
- Provider-specific rate tables (`tavily_rates`, `octen_rates`) have exact mode-key contracts:
  validation rejects incomplete, extra, non-finite or non-positive rates, and the runtime repeats the
  check before reserve so catalog drift cannot turn a platform call free. Their platform request
  bounds never rewrite the caller's body and do not apply to a team's own key.
- Where a provider bills one usage SKU at different prices per mode, each price is its own row with
  a `mode` enum.

### Provider-file declarations

- **`ceiling_param: {in: query, name, unit: usd}`** (provider file or one endpoint's `cost`): see
  AGENTS.md non-negotiable 4 and [money](money.md#caller-cost-ceilings). The provider rule lives on
  `Catalog.ceiling_params`, not copied onto every cost; a row-level declaration overrides it.
- **`client_header: x-<name>`**: the header the provider reads to split usage, errors and cost per
  customer on treg's one account. The loader keeps it on `Catalog.client_headers` (core file first);
  the validator requires a lower-case `x-` name that is not `x-treg-*` or a credential header. The
  relay fills it only on treg's shared key ([proxy-model](proxy-model.md)).
- **Header `queryParams`**: optional query parameters every endpoint of the provider accepts. The
  loader merges them into each endpoint's `input.queryParams`; the endpoint's own name wins, and the
  core file's block wins over the extended file's, so one block in core covers both tiers. None may
  be `required`.
- **`spooled_response: true`**: a synchronous endpoint whose answer inlines media too large for the
  8 MiB settlement buffer. Its metered 2xx settles from exactly the paths its row reads
  (`resolve._spool_evidence_paths`), so evidence cannot drift from price. A fixed price needs an
  `expect` rule so a refused generation is not billed; the validator refuses the field beside
  `async`, `resource_ownership` or `managed_resource`, which need the whole body.
- **`pathParams` with an `enum`** is enforced on treg's key (the value names what the shared
  credential is spent on, such as a model); own-key calls relay any path.
- **`platform_request`** pins exact body, header or query values needed only on the shared
  credential. A `queryParams.*` pin must appear exactly once and is read as the pinned value's type,
  so a run option such as a spend cap can bound one call's cost. Resolution applies these and the
  provider-specific request guards in `resolve` only after selecting the platform offer and before
  reserve; a team's own credential keeps the upstream contract.

### Provenance - `confidence` is a claim about the PRICE, not about the route

`verified:` on an endpoint says the route answered; `cost.confidence: verified` says the money
figure was confirmed. They are independent.

| `confidence` | what earns it |
|---|---|
| `verified` | observed being billed on a real call (`source: observed`), or read from the provider's live rate card (`source: rate_card_api`) |
| `documented` | transcribed from the provider's docs or pricing page |
| `inferred` | a floor or the top of a published range; the note says what else applies |
| `unknown` | no citable figure; `value` MUST be null and `note` MUST say why |

The validator enforces: `value: null` iff `confidence: unknown`; a `verified`/`documented` price
names its `source_url` (except `source: observed`, whose evidence is the captured example); every
priced entry has `checked`, with a CI warning past 90 days; a file whose header says `UNVERIFIED`
caps its prices at `documented`. Free is spelled one way - `type: free, value: 0, currency: USD,
unit: call` - and needs no provenance. `scripts/catalog_cost_provenance.py` owns provenance for the
extended tier, because anything typed into a generated file is lost on re-ingest.

### Platform-eligible - when treg may serve a catalog fallback

`Catalog.platform_eligible(endpoint)` is the single predicate shared by API, validator and proxy.
It requires ALL of:

- `cost_view(...)["usd"]` is not None: the charge is machine-computable;
- `cost.confidence` is `verified` or `documented`, or the route is `type: free` (a free route has no
  number to trust; a PAID route without provenance is refused);
- `scope != own_account` and `kind != account`;
- no `platform_blocked` and no `status` marker.

The `verified:` stamp is not required: a broken route fails unbilled under success billing,
in-band reporters settle at 0, and caps bound the rest. Eligibility alone enables nothing: a
normal platform call also needs a configured key and the provider allow-list (`platform_key_for`).
A missing or unknown price reads as "refuse", never as free, so unpriced extended routes need no
annotation. A row with only `observed_cost` gets a synthesized block from `_effective_cost`
(`source: observed, confidence: verified`, `checked` = verify date). Whether a provider's plan
licence lets treg serve other teams decides whether it gets an `fx.yaml` rate at all; the provider
file's header records that judgement.

`platform_auth: anonymous` is narrower: validation accepts it only on live-verified, free `GET`
operations with `scope: any_account`, no authorization metadata and no shared async-resource
lifecycle. After the team-tool and team-credential tiers miss, `_anonymous_offer` builds a virtual
tool with an empty binding list and tier `anonymous`; it needs only the provider allow-list
(`platform_provider_enabled`). The call runtime holds no provider or path list. Routed ranking keeps
own key first, anonymous second, paid platform third.

## Provider objects on treg's shared account

`managed_resource` is the generic contract for durable provider objects: CRUD operation, resource
kind, id location (path/query/body scalar or array, or create response), optional display-name
source, create-compensation endpoint, and an optional public-resource verification read. It is the
narrow exception allowing an otherwise account-kind tool onto a platform key: the runtime proves
org ownership locally, or verifies an unassigned id against the public predicate after closing the
DB session, before relay. An id assigned to any org is never sent through the public lookup. BYOK
never applies it. `application.provider_resources.list_for_caller` is the one read of durable
objects for HTTP, dashboard, CLI and MCP: the provider's own list when the team holds its own key,
else the team's `ProviderResource` rows in the same shape; its access-check session closes before
provider I/O.

`team_label` lists request fields that must carry the calling team's stable label
(`resolve.team_label(org_id)`) for provider objects kept per label on the shared account
(monitors, schedules, feeds). `_enforce_team_label` checks on the shared key only, before reserve,
without rewriting; a missing or foreign label is a 400 naming the expected value.

`caller_email` lists request fields (nested paths allowed) that on the shared key may only carry the
caller's own verified email (case-insensitive); another address is a 400 before reserve, omission
is fine. `_enforce_caller_email` never rewrites, so a shared account alerts only the person who asked.

For a signed-in reader, `GET /catalog/endpoints/{id}` (and MCP `catalog_get`) adds `your_values` on
rows with either field: the exact values that reader may send. The route is not edge-cached. MCP
`my_tools` also returns the team's `team_label`.

`response_retention: forbidden` (provider or endpoint; a provider declaration is inherited at load)
is distinct from `cache: forbidden`. The latter prevents archive storage and replay; the former also
suppresses response bodies in call events, failure evidence, idempotency bodies, routed parent
output and Web Arena records. Idempotency keeps a body-free 410 receipt so the same key cannot call
the provider again. `/call/` still returns the body to the active caller.

## Authorization metadata and paths

An endpoint may declare `authorization_method`, ordered `authorization_methods`,
`authorization_paths`, `required_scopes`, `required_resource` and `token_type`. `_normalize` keeps
them and endpoint detail exposes them only when present; marketplace resolution uses them for
preflight and grant selection ([instagram-oauth](instagram-oauth.md)).

Meta publishes its Graph reference only as HTML, with no machine-readable OpenAPI document.
Reviewed Instagram `input` and authorization contracts are therefore curated catalog data that
ingestion carries forward instead of erasing on a later scrape.

Path placeholders are percent-encoded by the marketplace caller; a value that already contains a
valid `%HH` escape is kept verbatim so callers can reuse encoded resource names an upstream
returned, while a literal `%` becomes `%25`. Where a provider's resource name is a hierarchy rather
than one opaque id (Google Tag Manager), the catalog exposes atomic placeholders
(`catalog_ingest.google_flat_path_params` follows Discovery's `flatPath`) so no slash-delimited name
passes through one placeholder and becomes `%2F`.

A verification stamp proves only what the evidence observed. A placeholder path value or a free
miss does not prove a paid hit; such rows keep the documented price and say which paid behavior
remains unobserved.

## Async descriptors

`catalog_store._normalize` sets `cache: forbidden` for every `image-gen`, `video-gen` and `voice-gen`
endpoint (including utilities and generated rows): these requests must reach the provider, never
replay shared-account task ids or media from an identical prompt.

An asynchronous submission may carry `async:`; a provider file may set a top-level default. An
endpoint block **replaces it whole** (`effective_async_descriptor`): a descriptor is one protocol,
and protocols that differ in one axis differ in poll target, status words and result location
together. `async: false` opts an endpoint out of the default.

```yaml
async:
  id_from: task_id
  poll:
    endpoint: minimax.video-gen.task.status
    param: {in: queryParams, name: task_id}
    # or: url_from: polling_url, url_hosts: [api.example.com]
  status: {path: task.status, success: [succeeded], failure: [failed, cancelled]}
  result:
    path: task.content.url
    # or: fetch: provider.video-gen.result.retrieve
    #     fetch_param: {in: pathParams, name: video_id, value_from: id}
    ttl_note: 9h
  interval: 10
```

Validation of the effective descriptor: dotted paths; non-empty `success`; `failure` may be empty
only when `billed_failure` supplies terminal failure words, or the descriptor has `max_age`; optional
`progress` names expected non-terminal words; status lists are disjoint; positive `interval`; poll
has exactly one of `endpoint` or `url_from`, result exactly one of `path` or `fetch`; unknown keys
fail. Static poll/fetch ids must be same-provider GET utility endpoints; poll `param` is exactly
`{in, name}` and `fetch_param` exactly `{in, name, value_from}`, and the named input must exist on
the target. Body-mode polling is outside the contract. Dynamic URLs need a non-empty `url_hosts`.
An async endpoint must use `per_success` or `per_call`. Status values compare after string coercion;
a missing or unknown value means still in progress in both the CLI awaiter and the worker (the CLI
warns once for a value outside `progress`). A `billed_failure` is a CLI failure that settles usage
instead of releasing. The call router serializes the descriptor into `X-Treg-Async` before the
response stream starts; it never inspects or buffers the upstream body.

- **Poll mode.** Every listed provider polls a static catalog id, reachable through `/call/<id>` on
  any tier. The dynamic-URL mode (`poll.url_from` + `url_hosts`) stays in schema, validator and
  worker, but works only for a team's own key: `/call/https://...` resolves only a team's own tool,
  and a host-allow-listed relay on the platform key is not built. Do not document it as available.
- **Envelope errors.** `application.call.service._submission_accepted` gates deferral on the
  endpoint's `expect`, so an HTTP-200 error envelope releases at once instead of becoming a task
  nobody can poll.
- `terminal_example_response` is the poll's final fixture used by adapter verification, while
  `example_response` stays the submission shown by the catalog.
- `terminal_on_submission: true`: a submission whose own status is already a success word settles
  like a synchronous call (read through `domain.asynctasks.finished_on_submission` by the direct
  path, routed bridge, Enrich Arena and `treg call --await`).
- `max_age` (seconds, at most a day) is the provider's polling window: the worker times the task out
  there and no waiter waits past it. `interval` also paces the CLI awaiter; treg does not count
  polls across pollers.

### Resource ownership on the shared key

`resource_ownership.produces` maps response paths to provider-local resource kinds (`tasks.*.id`
takes every list item); `requires` binds a path/query parameter to a kind. On treg's shared key a
2xx producer records the opaque id for the caller org, and a consumer is refused before relay unless
the same org owns that provider/kind/id. Ownership is only as trustworthy as the producer: a provider
that dedupes on `Idempotency-Key` could hand one org another's job, which is why the relay
re-scopes that header per org on treg's key ([proxy-model](proxy-model.md)). BYOK ignores this
metadata. Formal descriptors also materialize poll/fetch ids under endpoint-namespaced kinds, and
their utility rows declare matching `requires`, so a later catalog edit cannot silently turn a
protected endpoint fail-open; `AsyncTaskRecord` stays the authority for older tasks. A catalog test
rejects platform-eligible task/status/result reads that take a required id without this metadata
(`tests/test_dataforseo_async.py` holds every shared-key submission to an owned reader). Generated
task consumers with no trustworthy producer chain are `platform_blocked`. `carry_verification`
preserves reviewed ownership blocks across re-ingest; regenerating them away would reopen the
tenant boundary.

### Core-wins dedup compares NORMALISED paths - except on Graph

Core and machine specs never agree on placeholder spelling (`{property_id}` vs `{property}`), so the
Google and X ingesters compare with every `{...}` collapsed to `{}`. Meta uses exact comparison,
because on the Graph API the node id IS the first path segment: `/{post_id}/insights` and
`/{page_id}/insights` differ only by placeholder name and are different endpoints. Normalising there
would silently drop post insights because core curates page insights.

## Process - adding / curating a provider

1. **Ingest.** If the provider publishes OpenAPI, list candidate operations from it; do not
   hand-transcribe paths (that is how typos ship). Otherwise work from official docs and record
   `source.openapi: null`.
2. **Select.** Curate, don't mirror: the endpoints an agent would reach for, ALWAYS including the
   capabilities other providers already implement (overlap is the point).
3. **Map.** Assign a capability; a missing job goes under `proposed_capabilities:` in your file.
4. **Describe.** Fill `input` from the spec; copy real constraints ("one of A|B") into `note`.
5. **Cost.** Record the price model with provenance and unit. Unknown value means `value: null` +
   `confidence: unknown` + a note. Prefer a rate-card endpoint (`source: rate_card_api`): it is
   re-checkable, which is what lets treg serve the route on its own key.
6. **Test-request.** Smallest limit, one item, a public well-known target. Never probe with empty
   params "expecting a free validation error": an endpoint with no required params answers its full
   default result set and bills for it. On row-quota APIs check usage before and after the first call.
7. **Verify + capture.** `TREG_CATALOG_CRED=... scripts/catalog_verify.py <service>.yaml` calls each
   `test_request`, checks `expect`, writes truncated examples. Stamp `verified:` ONLY on passes. Every
   new row gets `added:` (`scripts/catalog_added.py`).
8. **Scrub.** See "Security" below.
9. **Validate.** `scripts/catalog_validate.py` must exit 0.

A provider PR: validator green; every endpoint verified with an example or explaining why not; no
credential value anywhere in the diff.

## Process - bulk-ingesting the extended tier

`uv run python scripts/catalog_ingest.py <service>|all [--refresh]` owns `<service>.extended.yaml`
end to end. Downloads cache under `~/.cache/treg-catalog-ingest` (`TREG_INGEST_CACHE`); output is
byte-deterministic, so a diff means the provider changed. A new provider adds an `ingest_<service>()`
to `INGESTERS`, honouring:

- **Never probe with a real call.** Discovering a method by sending GET bills every route it
  touches. An `OPTIONS` preflight is answered before the handler (and meter) runs.
- **The published spec outranks the probe** (`resolve_method`). treg enforces the recorded verb, so a
  wrong method makes the endpoint uncallable from both sides. A preflight answering with a method
  list comes out `GET` whatever the handler takes, so a spec declaring exactly one method wins.
- **The verb and the parameter POSITION come from one document.** When the spec declares a JSON body
  and the docs gave none, the documented "query" parameters ARE that body.
- **Platform is the system the data is ABOUT**, not the API family (`/v3/merchant/amazon/...` is
  `amazon`); anything not tied to one system is `web`. New slugs go into `capabilities.yaml` in the
  same change; the script exits non-zero on an unknown one.
- **Normalise slugs across providers** (`douyin-tiktok-china` and `douyin` must both land on
  `douyin`), or the shelf splits and comparison silently stops working.
- **The parameter source must give example VALUES.** An invented id produces a 404 that looks like a
  broken endpoint; without examples the honest output is `untestable`.

### Catalog rot

A `verified:` stamp is evidence about one day, and a re-ingest against an old cache reproduces old
truth. `scripts/catalog_drift.py` downloads each provider's cited public OpenAPI document with no
credential (salvaging a truncated JSON `paths` map, or YAML) and compares every checked-in
`(path, method)`. An unmarked missing path, a method change, or a marked route that reappeared
exits non-zero; known absent marked rows are `acknowledged`. `catalog-drift.yml` runs it daily for
the providers it lists.

### Retired and broken endpoints are tombstones, not offers

```yaml
status: retired                 # or broken
status_note: why it is gone and what changed
superseded_by: provider.live-id # optional; only when genuinely equivalent
```

`catalog_store._parse` keeps the row in `by_id` but out of `endpoints` (search, browse, counts,
eligibility). A direct catalog call gets an actionable 410 from `_resolve_marketplace_call` before
any credential is chosen (audit class `retired`); `/catalog/endpoints/{id}/access` applies the same
gate. An org tool with the exact id still resolves first, and URL passthrough never enters catalog
lookup. The validator requires a non-empty note, forbids `status_note`/`superseded_by` without
`status`, and requires a successor to be a different, existing, live id. A route that still returns
200 while ignoring the caller's spend control is broken in the costliest way and is retired too. A
successor written from the spec without a live probe says `skipped` with no example; an invented
fixture is worse than none.

### Paused providers - a deployment setting, not a row

`TREG_PAUSED_PROVIDERS` names providers this deployment cannot serve now. `store.paused(ep)` takes
their rows out of `_match` (search, candidates, near misses, rank band), `added_rows`, find's recall,
`_capability_alternatives` and routed plans. `by_id` keeps them, so a direct lookup or call answers
`503 provider_paused` (`interface/api.md`). Lifting the pause restores them unchanged.

### `platform_blocked:` - works upstream, but not on treg's plan

For a route that works but that treg's own subscription cannot serve (a plan-gate 403 on the shared
key). `status: broken` would be a lie (a caller's own bigger plan serves it), and leaving it
unmarked sells an offer that fails after planning. `platform_blocked: <reason>` keeps the row in
discovery, makes `platform_eligible()` refuse it, and rides on the served row so every surface says
"bring your own key" before the call.

### First-party OAuth providers

- **Google Discovery documents** (`https://<service>.googleapis.com/$discovery/rest?version=<v>`)
  are the source class to prefer over HTML reference. Scopes are ALTERNATIVES (any one suffices), so
  coverage is an intersection. The My Business documents declare no scopes.
- **Google Tag Manager** keeps risky administration outside the grant: methods needing container
  deletion or account/user management carry `scope_gap`, and those scopes are never requested.
- **Google Ads is a resource list, not a route list.** One endpoint (`googleAds:searchStream`)
  answers every read; entries share a path and differ in `input.note` and `docs_url`.
- These routes need an id belonging to the connected business, so they carry no `test_request` and
  are verified by replay against a live connection (`--via-treg`).
- **Instagram Messaging is core-curated only.** Listing targets the linked Facebook Page
  (`/{page_id}/conversations` with `platform=instagram`) and replies use `/{page_id}/messages`, not
  the Instagram account id; the send route stays unverified so no sweep delivers a real DM. The
  generator omits both routes.

## Process - bulk-verifying the extended tier

```
TREG_CATALOG_CRED='<secret>' uv run python scripts/catalog_verify_extended.py <service> --dry-run
TREG_CATALOG_CRED='<secret>' uv run python scripts/catalog_verify_extended.py <service> --budget 1.80
```

The run goes cheapest first and stops before a call that would pass `--budget`; results are written
back after every run and verified rows are skipped, so an interrupted run resumes.

- **A missing `cost` reads as free and silently disables `--budget`.** `observed_cost` (the charge the
  provider states in its response, written at verify time) budgets the next run. `observed_time` is
  measured wall-clock, never read from the body (a provider's `time` field may be a timestamp).
- **Spend accounting assumes per-success billing.** On a per-call provider compare the printed
  balance delta with the estimate before trusting a large run.
- **Respect per-route rate limits**, not just the account-wide one: a same-route retry must wait
  out the window (`PER_ROUTE_GAP`), and a 429 is retryable, not an answer.
- **Read recorded failures before believing them.** A repeating 400 is a verdict; one that passes on
  retry is a flaky upstream; a 429 is usually our own pacing. Failures aligned with a batch boundary
  point at tooling, not endpoints: after fixing a tooling bug, re-run every batch that ran before
  the fix. Retry until the result stops changing, not until it works; on a `per_call` provider every
  retry is a purchase. Two scrapers of one platform are one point of failure.
- The provider decides what counts as success: an HTTP 200 carrying an error is billed under
  `per_success` if the provider charges it.
- Sample captured examples per platform family for PII before committing.

`bodyType: form` means form only: the verifiers move a form-body credential into the body, a JSON
body sent to such a row is a 400 naming the fix before any upstream trip, and the MCP `call` tool
form-encodes an object body for it. A row whose upstream also takes JSON declares `json`.

## Choosing between providers (`domain/catalog/stats.py`)

**On a direct call the agent chooses, not treg.** Providers of one capability take different
requests and sometimes ask a different question (a domain and a name vs. a LinkedIn URL). **Only the
caller knows which inputs it holds.** treg chooses only when the caller calls a routed endpoint,
whose contract is a canonical schema ("Routing" below).

`TREG_ROUTE_PROVIDER_SAMPLE_PCT` optionally maps provider slugs to integer percentages from 0 to
100. In `application.call.route.build_plan`, a shared-key candidate joins a routed plan only for
that percentage of provider, org, capability and canonical-question hashes; a retry of the same question
gets the same decision. A missing or empty setting leaves all providers eligible. Unlisted
providers, direct calls and a team's own credential are unaffected. This gates eligibility, not
the eventual share of served calls or the provider's direct-call volume.

What treg supplies is what only it sees: **success rate, p50/p95 latency, last success and sample
size** per endpoint from folded `CallRecord` evidence, on `/catalog/endpoints/{id}` for the endpoint
**and every sibling**, because the choice is made on that page. The same page discloses the overflow
price when the deployment can relay it (`routers.catalog._overflow_disclosure`: `overflow_price_usd`,
`overflow_price_unit`, `overflow_via`; MCP `catalog_get` lifts them) - the price a free endpoint can
bill when treg's own account is out.

### Observations: folded off the request path, cached per process

- `stats.EndpointObservationReader` is the domain port; bootstrap wraps
  `PostgresEndpointObservationReader` in `CachedEndpointObservationReader` and hands the same
  instance to HTTP and MCP search, routed planning and the prose pages that print stats, so no
  request path checks out a connection for observations. Entries are fresh, then served stale while
  one process-level singleflight refresh runs, then withheld (`FRESH_TTL_S`, `STALE_TTL_S`); a
  failed refresh keeps stale entries without renewing their age and backs off. A cold process
  answers without reliability weighting; `observed` is `null` when no acceptable entry exists. No
  cross-instance correctness depends on the cache.
- The fold (`application/catalog_stats.py`, run by `treg-worker catalog stats`) walks `callrecord`
  by primary key from `EndpointStatCursor` into one `EndpointDayStat` per endpoint per UTC day:
  counts, last success, hit and verdict tallies, and a bounded uniform latency reservoir. Rows
  younger than sixty seconds wait (late audit commits); tool calls without `endpoint_id` and treg
  refusals (`refused_by`) are not evidence. Each batch is one transaction under the cursor lock and
  re-reads its buckets, so overlapping runs serialize instead of erasing each other's fold. The
  reader requires a recent caught-up fold; otherwise it raises `EndpointObservationUnavailable` and
  never falls back to scanning `CallRecord`. A deployment without the worker publishes nothing.
- `observed_from: YYYY-MM-DD` on an entry (with the reason as a YAML comment) drops day buckets
  before a provider replaced the service behind it.
- **Late terminal evidence.** `audit._write_batch` updates the matching `CallRecord` and calls
  `catalog_stat_dirty.mark_dirty` in the same transaction (`EndpointStatDirty`, keyed by endpoint and
  original UTC day; repeats bump a revision). The worker replaces marked buckets from source rows
  under the cursor lock and acknowledges only the revision it read. `catalog_stat_dirty` owns marker
  writes; the worker owns transactions. Async endpoints with result adapters publish only when
  every applicable day is `terminal_reconciled` and no correction is older than `STALE_AFTER_S`;
  one untrustworthy day suppresses the endpoint's whole observation, because dropping the day would
  bias its rate. Async hit rates use terminal evidence only. `catalog_stats.requeue_async_stats` and
  `repair_status` are the explicit, manifest-driven requeue and its completion check.
- Merging days weights each day's latency sample by the calls it stands for (`Tally.merge`), or the
  window's p95 would be the quiet days'. `stats.Tally` is the one shape for a day, a window and the
  live aggregate; `tests/test_catalog_stats_refresh.py` holds fold and SQL equal.
- The public `/rankings` boards are built by `treg-worker rankings refresh` into the one
  `rankingssnapshot` row from day buckets only (never `CallRecord`); the page reads that row. The
  last complete day precedes both today and the fold's watermark. Usage boards have no floor on
  purpose (they show a tool's volume, never a team); boards that rate or compare have floors so a
  small base cannot make a large percentage, and async endpoints are left out of reliability and
  speed.

### Rules for the published numbers

- **A 4xx never counts against the provider**; only 2xx versus 5xx decides the rate. **405 is the
  exception**: `/call/` refuses a method mismatch before relay, so a provider 405 says the RECORDED
  method is stale and counts against the endpoint.
- **A treg refusal is not evidence**: rows with `refused_by` never reached the provider and are
  excluded even from `samples`.
- **Below `MIN_SAMPLES` decided calls we publish the count and nothing else**, not even a yes/no:
  the floor counts decided calls (2xx + provider faults), so caller 4xxs cannot lift a rate into
  view, and on a quiet endpoint a rate could expose one org's outcome. Latency has its own floor of
  successful calls. "Never worked" is read off `ok_rate == 0` over decided samples only.
- **Sample size is always visible**, so `100% (8)` cannot beat `99% (121)` by looking rounder.
- **`last_ok` means the last SUCCESS**, and a `verified:` stamp shown in its place is marked as a
  claim (`✓` age), never dressed as a measurement.
- **An empty answer is a failure where the job demands content.** A contract marked
  `empty_is_failure` counts a 2xx whose `CallRecord.hit` is False as bad (`store.empty_is_failure`),
  including a 2xx naming its own error in the body (`provider_error`). Every tool of those
  capabilities callable on treg's key needs a verified adapter and a miss (the adapter's, or a v2
  row's own rule); tools outside routing carry a
  judge-only adapter (`route: false`). A test enforces it.
- **`miss` semantics ride on the endpoint.** A `miss: {status, means, when?}` block declares an error
  status meaning "asked and answered: no result". Router, arena and hit verdict read it through
  `routing.contracts.declared_miss`: the waterfall continues, a fully-missed call is a 200 miss, and
  `CallRecord.hit = False`. Only a 4xx is honoured (a 2xx is the adapter's call). `when:` is a body
  predicate in the adapter language for statuses that carry both a miss and a fault, evaluated only
  on a JSON object; the validator rejects a `when` that is not a comparison or call, since a misspelt
  path would evaluate False forever. Annotate only what the wire has demonstrated; a `per_call`
  provider still bills its declared miss.
- **`not_found` ends a routed call.** `not_found: {status, when?, means}` says the target itself does
  not exist, so every other provider can only find the same nothing. `route.py` ends the call with
  `route_not_found` (404 for a 2xx declaration), charging nothing and asking no one else.
- **A failed `expect` rule is a miss** for a routed child, free on `per_success` unless the provider
  reported a charge. `route.py` never names a provider; provider knowledge lives in YAML.

### Search scoring — most words must match, and the rare ones decide

This is what `/catalog/search` answers and what an agent's MCP or CLI search falls back to when the
job-first answer abstains ([discovery experiment](find.md)). `scripts/search_bench.py`
replays labeled agent queries; run it before and after a scoring change.

- A query word matches only at the START of a word (`store._needles`, word-padded haystacks):
  "search" matches "searches" but not "research". A provider's one-word name shorter than
  `WHOLE_WORD_BELOW` letters matches only whole (or plural), so "exa" does not match "exact". CJK
  text matches anywhere.
- **A provider named with a task** (`store.provider_focus`): the name is removed from the query, the
  provider's rows need one remaining word (stem match allowed) and lead in their own order with no
  routed row; every other row is scored by the remainder as an ordinary search. The page says
  `led_by` and shows no score. If none of the provider's rows matches, the query runs as typed.
- A query may miss one token in three (1-2 words: all required), and each matched token scores field
  weight times BM25 idf, so dropping a rare word costs more than dropping filler. Function words and
  single letters are dropped before the allowance is computed. Tokens matching over
  `SOFT_DF_SHARE` of the catalog are soft: they add score but missing them is never punished.
- `aliases.yaml` bridges vocabulary query-side only (substring containment works one way). NOUNS
  ONLY: aliasing a verb to a commoner verb destroys the key's ranking power. Keys are one token;
  targets may be hyphenated phrases (`t2v` to `text-to-video`). Do not alias generation task words to
  bare `video`/`image`, which pulls in unrelated utilities. `check_aliases` rejects entries the
  tokenizer cannot survive and warns on targets absent from the catalog. The SearchMiss log is the
  feed for new aliases.
- A platform-slug token is the caller's hard filter but idf prices it low, so it scores DOUBLE.
- A zero-result answer returns `near_misses` with the words each row matched and missed (MCP `near`,
  an HTTP hint, CLI "almost:" lines), so the calling LLM can re-query correctly.

### The evidence decides the ORDER

Token scores tie by the dozen; `catalog_store.rerank()` breaks ties over `rank_band()` on buckets,
not a blended formula: **relevance, then measured (good / unknown / poor / never worked, from
`ok_rate` alone), then core before extended, then price.** Evidence outranks curation (a core row
that never answered is not better); curation outranks price (a tenth of a cent must not promote the
bulk-ingested tail); unmeasured sits above measured-poor. `rank_band()` takes a tie group whole,
bounded at `RERANK_BAND` on this open route, and **says when it truncated** (`ranking_note` on MCP,
an HTTP hint).

`CapabilityPin` ([data-model](data-model.md)) fixes a capability to one provider, enforced in
`_resolve_marketplace_call` before reserve. A pin gates the catalog id, the only route to treg's key;
a team's own key for another provider remains callable by URL, and `DenyRule` is the tool to block
that.

### Routed groups in discovery - a search page is a list of JOBS

Shared by `/catalog/search`, MCP `catalog_search` and the CLI through `group_routed` / `search`:

- **A matched child brings its routed parent** (`treg.<capability>`) at the best child's score,
  unless the query named the provider with a task.
- **Vocabulary before ranking**: when a job ranks wrongly, say what the job is in
  `capabilities.yaml` (and `aliases.yaml`) rather than bending the scorer.
- **A group shows its best `MAX_ROUTED_CHILDREN` children**; an approved hub tool of the same job is
  never cut. The parent carries `children_hidden`. Search ranks a band of four times the page (at
  most 100) and cuts to `limit` after grouping.

## Routing - first-party routed endpoints (`treg.<capability>`)

The one place treg **models** an upstream API, and the explicit opt-in where the caller asks treg to
choose. Everything else stays verbatim relay. The response contract and the `X-Treg-Route-*`
headers are agent-facing in `src/treg/web/skill.md`; the invariants are AGENTS.md non-negotiable 4.

### Contracts (`contracts.yaml`)

Per capability: one-of identity variants (structural keys, never provider names), `derive` rules,
a small output core and `miss` in canonical terms. `raw` (the winning provider's body) is always
returned and never documented as stable. An output field may say where it lands in a call event
(`analytics`, [call-events](call-events.md)); the public contract view drops it.

- `advice_unverified` is attached as `_treg.advice` to a hit whose `verified` is not true (a found
  contact is not a confirmed one); a search contract has no `verified` output, so its advice
  attaches to every hit. treg never chains a verify call by default.
- `check` (opt-in via `X-Treg-Route-Verify`): after a hit `_run_check` runs the check endpoint as an
  ordinary linked child `:v` through `execute_call`, with its own hold and charge, the cost ceiling
  the find left, and `prefer` applying to that call only (below the team's own key). A check that
  does not fit, is refused or fails never fails the find (`checked: false` with a `reason`, cost 0;
  `no_hit` when the find missed). A direct (non-routed) check leaves its hold in the find's
  `pending`; the find's holds stay open during the check so cancellation releases both. A check
  still pending after the routed async wait reports `cost_micro`, `pending: true`, its `call_id` and
  poll descriptor. Once a check ran the find's advice is dropped, except that a completed verdict
  other than `valid` on a `verified: true` hit attaches `disagree_advice`; `output.verified` itself
  is never altered. A check's `when` and `skip_reason` skip a hit before any call (a phone not in
  international form is `not_international`, because HLR reads national digits as a country code),
  and its `skip_advice` replaces the find's advice. The header on a contract without `check` is a
  422 before planning.
- `confirm` (opt-in via `X-Treg-Route-Confirm`) names the field two DIFFERENT providers must agree on
  (trimmed, case-folded); two endpoints of one provider never confirm each other. The earlier hit is
  the answer; with no agreement before candidates or ceiling run out, the first hit returns marked
  unconfirmed.
- `verdict` declares the per-call word stored on `CallRecord.verdict`: `from` field, closed `words`,
  `map`. It is read only from an answer that fills the required output, and is independent of
  `miss`. `verdict.decisive` (opt-in via `X-Treg-Route-Decisive`) keeps a non-deciding answer as
  `weak` and asks at most `MAX_WEAK_FALLBACKS` more providers; after the first attempt the rest are
  reordered by measured quality (`routing/quality.py`, expected net correct verdicts per call;
  endpoints below `MIN_COMPARABLE` compared verdicts keep price order behind rated ones; a caller's
  `X-Treg-Route-Prefer` is never reordered). The numbers come from an operator scorer's
  `<route_quality_prefix><capability>/routing.json` in a private bucket (`infra/route_quality.py`,
  cached; a request waits at most a second on a cold cache); without it the header keeps price order.
- Confirm or Decisive on a contract without the declaration, or with `X-Treg-Route-Waterfall: 0`, is
  a 422 before anything is held.
- `routed: false` declares an admission-only contract: its adapters verify (the archive's
  `has_result_rules` reads them) but no `treg.<capability>` row is generated. For a capability whose
  "children" are one provider's price tiers.
- `question_miss` is a miss rule that also sees the question: `child_outcome` evaluates it on the
  caller's identity merged with the child's core output, after the adapter's own `miss`, and a hit it
  marks true becomes a miss (`why: question_miss`) the route moves on from. It names no provider;
  `no_result_on_site(q, results)` judges a `site:` question whose rows are all on other sites. A
  call without an identity (a replay record) is not judged by it.
- `scoping` names identity keys that scope the answer (`company_domain`): a candidate whose adapter
  never sends a supplied one is dropped from the plan, not ranked down, because a title-only search
  asked for one company's CEO bills title-matched strangers as a hit.
- `prefer` is the default provider order when the caller sends no `X-Treg-Route-Prefer`. Cost per
  hit ignores time, so a contract may prefer a dearer but faster, more reliable provider.
- `prefer_by_domain_suffix` maps a suffix of the identity's `domain` to providers asked first, ahead
  of `prefer`, when the caller sends no `X-Treg-Route-Prefer`; the longest matching suffix wins.
  Coverage differs by country while cost per hit is one number. The suffix only sees the company
  domain, so a French company on `.com` is not matched.
- A published route rule ([route-rules.md](route-rules.md)) goes ahead of all three when one matches
  the call's recorded segment and the caller sent no `X-Treg-Route-Prefer`; it changes without a
  deploy and, like them, only reorders.
- `prefer_when` lists `{sent: [identity keys], prefer: [providers]}` rules; the first whose keys the
  caller all sent replaces `prefer`. A matching domain suffix still goes first, and a caller's header
  still wins. One order does not fit every question: `people.search` asks its semantic searches
  first for a free-text `{q}`, and keeps `prefer` for company lookups that they cannot scope.
- `fill_limit_when` lists identity key sets (`[[q]]`) on which the caller's own `limit` is a row
  count to reach, not only a page size. When the caller sent exactly one listed set and a `limit` of
  2 or more, and neither `X-Treg-Route-Min-Results` nor `X-Treg-Route-Merge`, the route acts as if
  both were sent (`min_results = limit`, merge on). `people.search` lists only `{q}`: a free-text
  search asks for everyone who fits, while a company lookup stays one provider's answer.
- `one_subject: true` (person finds): every identity variant names the same person, so expected cost
  per hit ranks before specificity.
- `row` gives a list output one row shape whatever provider answered (`people.search`,
  `instagram.search.users`): `of` names
  the list field, `fields` the keys a row may carry, `needs` the keys of which a row must fill one.
  Each adapter's `row:` maps one provider row into it; a row it cannot read stays the provider's own
  rather than vanish from a paid answer, and an adapter without `row:` keeps its provider's rows.
  Text is cut to `ROW_TEXT_MAX` characters, because an agent pays tokens for every row it reads; a
  field of type `url` is kept whole, since a cut link points at another resource.
- List the most complete identity variant first: the first variant a caller fills is the one every
  field rides on.

### Adapters (`adapters.yaml`)

One per endpoint: `accepts` (identity variants), `in` (contract field to `queryParams.x` /
`body.x`), `in_expr`, `const`, `filters` (always sent), `out` (core field to expression), `miss`
(none on a v2 row's adapter: the row's own `miss` rule judges), `test_identity`, `row` (row field to
expression over one provider row, for a contract with a `row`), and `route: false` for a judge-only adapter (results, stats, cache admission;
never routing or arena). `verdicts` maps provider words (lower case, spaces and hyphens to `_`) to
the contract's; `verdict` is an expression for a provider that reports the word elsewhere. An
unmapped word is stored NULL and logged; `tests/test_call_verdict.py` holds every verifier's example
to a mapped word. `cost_units` gives an upper bound in catalog-priced units, used by both the quote
and the plan through `routing/plan.py::cost_at`. `max` (`{limit: 8}`) drops the child for a larger
request rather than letting it answer less than asked. `verified` is filled only from an explicit
mailbox deliverability verdict, never a lookup-success flag.

The expression language (`domain/catalog/routing/paths.py`) is deliberately tiny: dotted paths with
`[i]`, `coalesce`, `/ N`, `==`/`!=` against literals, and named generic transforms listed in that
module. They are generic helpers, not provider-specific rewrites; `raw` is never touched. A country
filter must never silently become a default country: `dfs_location` returns nothing for a value
that names no country, and a one-argument transform with no value counts the filter as ignored.

**Verified at load, or absent** (`routing/contracts.py::verify`): `in` must reproduce the endpoint's
own `test_request` and `out` must fill every required core field from its example (an example that
is a miss passes with the hit half unverified). A `row:` may name only the contract's row fields, and
every example row must fill one of its `needs`. A failing adapter is not a candidate; the endpoint
stays callable via `/call/`. `tests/test_routing.py` pins every shipped adapter. An adapter's
`additional_capabilities` are admitted through `verified_capabilities` only when the primary passes;
an invalid extra never disables the primary.

### The generated row, ranking and execution

- **The row** (`routing/synthetic.py`): every capability with at least two verified children gets
  `treg.<capability>` (`provider: treg`, `kind: routed`, `POST /<capability>`, `input` = the
  contract, `cost` = the children's range, `routed_children`). `miss_billed_by` lists children that
  bill an answer treg judges a miss; when non-empty the cost carries `varies: true` and
  `usd_per_call: null`, and the note leads with "Not free", because a $0 floor read as free to an
  agent that then paid for hundreds of billed misses. Never hand-written. `catalog_get` on it returns
  the contract and the ranked plan (nothing reserved); `store.quote_cost` cuts each row's cost to
  price and unit. A child treg would not call on its key ranks last with a `skipped` reason.
- **Ranking** (`routing/plan.py`): own keys first at cost 0, then the anonymous tier, then
  `expected_cost_per_hit = cost_at(request) x P(billed) / P(hit)`, where `cost_at` prices this
  request at its requested size and `P(hit)` is the published hit rate. Below the publication floor
  (`stats.MIN_HIT_SAMPLES` judged lookups) it is `UNMEASURED_HIT_PRIOR` (0.5) times `ok_rate`, or
  the prior alone while `ok_rate` is unmeasured too: assuming every unproven answer a hit put a child
  seen a few times ahead of same-priced siblings measured near 1. A per-success child bills no miss, so
  its cost per hit is its price either way; an unmeasured per-call child leads only below half a
  measured sibling's cost per hit, which still lets a much cheaper newcomer be tried and measured.
  Among one tier, a candidate that uses more of the keys the caller SENT outranks a
  cheaper one (never counting keys reached through `derive`), and one that ignores a sent filter
  ranks below every one that can express it (`ignored_filters()`, computed at planning so ranking and
  report agree; `limit` and contract defaults never count). An exhausted platform provider with an
  enabled overflow route stays a candidate at the overflow price; without one, or with no key on the
  deployment, it is dropped and named in `dropped`.
- **Execution** (`application/call/route.py`): each attempt is a full child `execute_call` with
  `call_ref` `{parent}:r{n}` and the ordinary hold, ladder, relay, settle, audit and cancellation.
  - Vendor 4xx (not 402/405/408/410/429) is usually the caller's fault, but scrapers answer 400 for
    their own outages, so the waterfall continues ONLY to candidates that bill nothing for a
    rejection (per_success, free, the team's own key, or per_call at most `CHEAP_RETRY_MICRO`),
    never the same provider. All rejecting means `route_caller_fault`. Once another provider has
    answered the same question, a 4xx is that provider's own (`rejected`) and the waterfall goes on.
    A declared `miss` status is a MISS.
  - 405 and 410 are the provider's own and fall over like a 5xx. Our 5xx/503/429 or a vendor
    5xx/429/402 is an error: next candidate, at most two extra, only for idempotent contracts. A
    child's `tool_access_denied`, `policy_denied` or `capability_pinned` refusal, and a platform
    child's vendor 401/403 (treg's credential), fall back the same way. Balance and spend-cap
    refusals are terminal.
  - Before planning, each identity field is type-checked (`invalid_identity`, 422, even when another
    complete variant was sent). A `url` must parse as an HTTP URL with a dotted host and no userinfo;
    a scheme-less one gets `https://`. A derived `linkedin_url` is built only from a handle-shaped
    value.
  - A 2xx lacking a REQUIRED core field is a MISS. The waterfall is on by default;
    `X-Treg-Route-Waterfall: 0` stops at the first miss. `X-Treg-Route-Min-Results: N` marks a thin
    answer `weak` and continues at most `MAX_WEAK_FALLBACKS` times, returning the fullest answer:
    unbounded, it would pay the whole ladder on lookups whose honest answer is one row.
    Under `X-Treg-Route-Merge` the distinct rows of every answer so far, not the latest answer
    alone, are compared with `N`, so the walk stops once the union reaches it.
  - **Holds.** A child that charges nothing releases at once, before the next reserves, or a
    balance covering each child in turn would 402 mid-waterfall. **A billed child never settles its
    own hold**: it leaves a `settle.DeferredSettle` and `run_routed` closes every one exactly once at
    the end (`settle.close_deferred`, one transaction): settled when the routed call answers (a hit
    or a 200 miss), released when it fails, including cancellation. A failed routed call therefore
    charges nothing (`charged_micro: 0`, `released_micro`); a crash leaves the holds to the reaper.
  - **Ceiling.** `X-Treg-Route-Max-Cost` (default `DEFAULT_MAX_COST_MICRO`, or the contract's
    `default_max_cost_usd`) bounds the sum; each child receives the remaining ceiling and the shared
    reservation gate checks its estimate with margin, including overflow. A budget refusal skips that
    candidate without using the error allowance. Before any child runs, 402 `route_max_cost` names
    the cheapest price (not the first-ranked) when nothing fits. A waterfall that skipped candidates
    for budget says `_treg.capped: true` / `X-Treg-Route-Capped: true`.
  - The parent owns the idempotency label (a success replays; a failure costs nothing, is not stored,
    and a retry tries again) and writes one audit row (`credential_tier: routed`).
  - **Async children** go through the shared async bridge: submit once, poll through ordinary child
    calls, pass the final poll body to the adapter. After `ROUTED_ASYNC_WAIT_SECONDS`, or when a poll
    cannot prove a declared terminal state, it returns 202 with `_treg.outcome: pending`, the child
    reference, poll descriptor and `reserved_micro`; a pending attempt stops the waterfall because
    the child may still charge, and the async worker owns settlement.
- **Hit rate.** `CallRecord.hit` is the adapter's verdict on a completed result (a judged 2xx, or a
  declared `miss:` status); other errors stay NULL. An async submission leaves it NULL; the terminal
  finalizer classifies the finished body and queues an audit update for the originating row
  (`AsyncTaskRecord.hit` keeps it if polling wins the race). A confirmed terminal failure is a miss.
  `stats.publish` publishes `hit_rate`/`hit_samples` above its floor; synchronous per-success
  endpoints also read historical rows (a 2xx with `cost_observed_micro == 0` is a miss), while async
  ones use only the terminal verdict, since a found result can cost zero credits. Verdict counts are
  folded into `EndpointDayStat.verdicts` but not published until the word mappings are proven;
  publishing them must keep the hit floor and use corrected terminal evidence.
- **Domain match on email finds**: with a caller `domain` (or `company_domain` / `website`) and an
  `email` hit, `_treg.domain_match` / `X-Treg-Domain-Match` disclose whether the mailbox host
  matches (as call events store `answer_flags.domain_match`); `advice_domain_mismatch` names it. The
  hit is still billed and unaltered.
- **The answer says what it ignored**: `ignored_filters` on `_treg` and `X-Treg-Ignored-Filters`.
  `X-Treg-Route-Strict-Filters: 1` drops candidates that cannot express a sent filter
  (`strict: true` in `dropped`) and answers 422 `route_no_candidate`, unbilled, when none is left; a
  503 stays reserved for capacity/key drops.
- **More rows than `limit` are kept and disclosed**: when the caller sent `limit` and the serving
  child (one that does not accept `limit`, or floors it) or a merge returns more list rows, every
  row and an honest `count` stay, and `_treg.limit_exceeded` / `X-Treg-Limit-Exceeded` name
  `{asked, returned, why}`. The extra rows are already billed and a routed answer is never altered;
  a contract default is not a question anyone asked, so it does not trigger the note. `limit`
  stays out of `ignored_filters` (a page size, not a narrowing filter).
- **A long provider cursor stays in `raw` only**: a routed endpoint takes no cursor, so
  `output.next_cursor` only serves a direct call to the serving provider. One longer than
  `CURSOR_MAX` (512 chars; icypeas returns tokens of many KB) is set to null and
  `_treg.next_cursor` names `{chars, in_raw}`, the adapter path where `raw` keeps it whole.
- **A stand-in reaches a provider the caller's fields cannot**: a contract's `stand_in` maps an
  identity key to an expression over the identity and filters (people.search:
  `q = join(full_name, title, location)`). `adapter_accepts` tries the caller's own fields first and
  builds the stand-in only when an adapter accepts none of them, so exa and parallel (`{q}` only)
  can answer a `{title}` request while every other provider's request is unchanged. The stand-in
  never enters the plan's identity; `to_upstream` fills it for the matched variant, and `unscoped`
  counts the keys inside it as sent. A key left out of the expression keeps its scoping guard
  (`company_domain`: a text match cannot scope by company).
- **Free text is a filter, not identity**: a brief's requirements ride in `keywords` (always sent),
  never in `q` alone, or a provider matching the `{title}` variant never sees them. Hard filters
  that broaden or over-constrain measured worse; add one opt-in, and measure it first.
- **Routed discovery is a runtime switch**: `TREG_ROUTED_DISCOVERY=off` hides routed rows from
  search (they match keyword queries on their own summary) and from the platform browse view, and
  strips the `<!--routed-->...<!--/routed-->` section of `/skill.md` and `/llms.txt` (markers are
  stripped either way), so docs never teach a row search hides. Rows stay callable and priced. One
  choke point (`group_routed`) serves `mcp.py` and `routers/catalog.py`; MCP narrows its rank band
  back to `limit` when off.
- **Not routed on purpose**: `*.bulk` endpoints (one subject, one answer) and teaser providers that
  need a search-then-reveal chain. `catalog get` lists them under ALSO. The routed example body and
  `/access` dry-run use the identity variant most children accept; `/access` gives each drop its own
  `why`, never a label that reads as a missing key.
- **Not built**: a `kind: filters` / `Location` layer for DSL/SQL providers; own-key-dry to
  treg-key fallback.

## Archive comparison declarations

The effective `cache:` block accepts `ignore_paths: [...]` beside `max_age_s` (default empty), with
the usual provider-header inheritance and whole-block endpoint override. `store._validate_cache`
rejects bad lists at load, including provider-header declarations an endpoint overrides. Paths are
case-sensitive dot-separated names matching `[A-Za-z0-9_][A-Za-z0-9_-]*` with `[*]` suffixes for
array elements (`data.items[*].updated_at`, `[*].request_id`); numeric indices, plain `*`, `$`,
escaping and recursive wildcards are rejected, and keys containing literal dots or brackets are not
addressable. `archive._normalized_hash` removes these paths only from a parsed copy for TTL equality;
it never changes stored or served data, raw hashes, dedup or hit/miss classification. Each
declaration carries a one-line reason; its evidence goes in the PR ([archive](archive.md)).

## Security

PII IS THE HARD RULE. This repo is public and every captured example ships in it.

1. **No named private individuals.** A contact-lookup route stays in the catalog but is marked
   `untestable:` with the reason and carries NO `test_request`, so a re-verify cannot re-capture it.
   No captured person response is stored. A routing adapter may use a hand-sanitized structural
   fixture only when its contact values use reserved fake domains/numbers, the verifier cannot
   refresh it, and separate live evidence establishes the mapped fields.
2. **No third-party PII riding along.** Sweep every example for email- and phone-shaped strings
   inside unrelated payloads (descriptions, reviews) and mask anything that is not a business
   contact.
3. **No first-party identity.** Own-account verification captures your own channel, site and
   metrics; point test requests at neutral public targets and scrub what was captured. Account-info
   endpoints of your own key (quota, balance) must have emails and ids masked.

Credentials are NEVER written into catalog files, examples, scripts or docs; the verifiers read
`TREG_CATALOG_CRED` from the environment only. Examples are truncated by the verifier, then
human-reviewed for PII before commit.

## Operator-supplied pricing evidence

`catalog_ingest.py` requires `TREG_CATALOG_EVIDENCE_DIR` for AnyAPI and JustOneAPI imports:
`anyapi_measured_charges.json` (`skus`) and `justoneapi_prices.json`
(`prices`). Missing files fail before any catalog output is written, rather than silently replacing
measured prices with estimates. Published catalog prices are public; private ledger exports and
account evidence are not, and hosted operators keep the inputs in their private repository.
