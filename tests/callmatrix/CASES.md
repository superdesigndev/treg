# call 状态矩阵 + 用户旅程 — 用例目录（自然语言版）

一个 PR 实现全部 30 个用例。本文件是测试的规格来源：每个用例先在这里说清
“布置什么、做什么、评估什么”，实现必须与本文一致；以后每次生产事故在此加一行。

公共机制：进程内假供应商（行为由 `X-Fake-*` 请求头点菜，记录每次收到的请求）；
故障注入传输层（模拟超时/断连/断流）；每个用例跑完统一核对“四本账”——
HTTP 响应（状态码、`X-Treg-Call-Id` 恒在、计量时 `X-Treg-Cost-Micro`、
`X-Treg-Error` 的有无）、账本（余额、流水原因、无悬挂预留）、审计行
（状态、refused_by、费用列）、上游命中数（假供应商实际收到几次请求）。
金额断言一律经 `with_margin()` 计算，不硬编码供应商原价。

## A 组 · 正常路径（4 例）— 校准“四本账”测量仪器本身

| # | 用例 | 布置与动作 | 评估什么 |
|---|---|---|---|
| A1 | 自有工具 GET | 注册 header 型密钥 + echo 工具；GET 调用 | 凭证被服务端注入（上游收到 Bearer）；响应逐字节回传；有 Call-Id、无 X-Treg-Error；**账本零变化**；审计 200；上游命中 1 |
| A2 | 自有工具 POST | 带 body + 重复 query 参数（?tag=a&tag=b）调用 | body 与重复参数原样到达上游；仍零计费——保真基线 |
| A3 | 目录调用 tier-4 | 开平台 key；调 tikhub 端点（$0.001 per_success）；上游 200 无实报费用 | 预扣→结算全链：`Cost-Micro` = 加毛利后的估价；余额减同额；hold 关闭；审计带完整遥测（endpoint/provider/tier=platform） |
| A4 | 自有 key 遮蔽 tier-4 | org 存入自己的 tikhub key；调同一端点 | **凭证阶梯**：上游收到的是 org 的 key 不是平台 key；零扣费；tier=own——“自有 key 永远赢”是产品承诺 |

## B 组 · 上游失败（7 例）— 钱的每条退路

| # | 用例 | 布置与动作 | 评估什么 |
|---|---|---|---|
| B1 | per_success 上游 500 | tier-4 调用，假供应商回 500 | 预扣**全退**（流水 reason=call_failed_500）；500 原样转给调用方；**无** X-Treg-Error（是供应商说不，不是 treg 拒绝） |
| B2 | per_success 上游 404 | 同上，404（查无结果） | “成功才计费”：未命中免费，全退 |
| B3 | per_call 上游 400 | 换 per_call 计费型端点，上游 400 | **失败也计费**——per_call 语义；400 在“非调用方之错”排除集之外 |
| B4 | per_call 上游 429 | 同上，429 | **退款**——429 属排除集 {401,402,403,405,407,408,429}；与 B3 成对钉住排除集边界 |
| B5 | 网络超时 | 故障传输注入 ReadTimeout | 502 + 全退；失败证据（脱敏的请求/响应片段）落审计行 |
| B6 | 连接被重置 | 注入 ConnectError | 同上——两类网络异常都走干净退款 |
| B7 | 计量响应中途断流 | 200 应答后 body 流中断（ReadError） | 缓冲失败归类为 call_failed（502）而非 call_crashed——异常类型决定流水原因，断言钉住这条归类 |

## C 组 · 计费边界（5 例）— 结算金额的每个分支

| # | 用例 | 布置与动作 | 评估什么 |
|---|---|---|---|
| C1 | 实报低于估价 | dataforseo 端点；响应体带 `cost` 字段且低于估价 | 按**实报**结算、退差额；`Cost-Micro` = margin(实报)——多退少不补的“多退” |
| C2 | 实报缺失 | 计量 200，响应体没有费用字段 | 回退**估价**结算——不收 0 也不炸 |
| C3 | 实报畸形 | `cost` 字段是垃圾字符串 | 解析失败 → 回退估价——健壮性 |
| C4 | 供应商无视压缩协商回 gzip | 请求侧已带 identity（在上游命中记录里验证），响应仍 gzip | 实报解析失败 → **按估价结算**（这是预期行为，不是按实报）——dataforseo 20 倍事故的回归界线 |
| C5 | 4xx 错误体是 gzip | 上游 4xx + gzip 错误体 | 证据链路会解压留痕（与 C4 对照：**证据路径解压、实报路径不解压**） |

## D 组 · 幂等（4 例）— 重试不重付

| # | 用例 | 布置与动作 | 评估什么 |
|---|---|---|---|
| D1 | 同 key 重放 | 成功一次计量调用（带 Idempotency-Key）后原样重发 | 返回**原响应体和原 Call-Id**；账本零新扣；上游命中不增加 |
| D2 | 同 key 并发 | 两个同 key 请求并发（第一个被假供应商拖住） | 后到者 409——数据库唯一约束抢锁，绝不打两次上游 |
| D3 | 同 key 换请求 | 同 key 但 query 变了 | 拒绝——指纹校验防 key 错用 |
| D4 | 失败后重试 | 第一次上游 500（已退款），同 key 重发且这次 200 | 失败会**释放**幂等占位；重试正常执行并只计费一次 |

## E 组 · 拒绝（5 例）— 上游零字节 + 必留审计痕

每例公共断言：**假供应商命中数 = 0**（所有闸门都在转发之前生效）、
响应带 `X-Treg-Error: 1`（treg 拒绝的标志，与 B 组“供应商说不”相对）、审计行带 refused_by。

| # | 用例 | 布置与动作 | 评估什么 |
|---|---|---|---|
| E1 | 余额不足 402 | 余额烧到低于估价再调 tier-4 | 402 的 body 是机器可自救的（balance/estimated_cost/topup_url）；审计费用列显式 = 0 |
| E2 | 每日调用上限 | 成员 cap=1，调第二次 | 拒绝生效；审计费用列 = NULL（早期闸门无遥测——**注释注明这是当前实现细节而非产品契约**，将来改变须显式改本行） |
| E3 | deny 规则 | org 配置 deny 覆盖该上游 host/方法 | 在**解析后的**真实上游 URL 上拦截（防重定向绕过语义）；费用列 NULL |
| E4 | 成员工具 ACL | member 的工具白名单不含该工具 | 拒绝；refused_by 与 E3 同为 policy（不试图靠此列区分二者） |
| E5 | demo org 调 tier-4 | public_demo 团队调平台端点 | 当前真实行为：落入通用 404（resolution），**不是** demo 专属 403（那只在 oauth-billed 路径存在）——钉住现状，防止误以为有专属拒绝 |

## F 组 · 转发保真（3 例）— 逐字节的承诺

| # | 用例 | 布置与动作 | 评估什么 |
|---|---|---|---|
| F1 | 重复 query 参数 | ?tag=a&tag=b | 上游按原顺序收到两个 tag——多值参数不丢不并 |
| F2 | 路径里的 %2f | /call/<tool>/a%2fb | 上游 raw_path 保留 %2f 不被解码——npm scoped 包类路径的保真 |
| F3 | cookie 清洗与头保真 | 请求带 treg_session cookie + 自定义头；上游回 Set-Cookie: treg_session=evil | 自定义头到达、**treg 会话 cookie 被扣下**（不泄给上游）；上游试图种 treg 会话 cookie 被拦（防会话固定） |

## G 组 · 并发（1 例）— 数据库裁决最后一分钱

| # | 用例 | 布置与动作 | 评估什么 |
|---|---|---|---|
| G1 | 10 并发抢 3 次余额 | 余额恰够 3 次估价，asyncio.gather 发 10 个计量调用 | **恰好 3 个 200、7 个 402**；余额精确扣到不足一次；无悬挂预留——条件 UPDATE 的原子性在 HTTP 层验证（sqlite 上为弱化验证，Postgres CI 任务落地后自动变严） |

## J 组 · 用户旅程（1 例）— 所有缝合处串成一条用户视角的线

| # | 用例 | 步骤 | 评估什么 |
|---|---|---|---|
| J1 | 注册到复购全程 | 邮箱验证码注册 → 确认 $1 赠额到账 → 建团队 → 存 secret 注册工具 → 调自有工具（验注入）→ 开平台 key 调目录端点（验预扣结算）→ GET /calls 两条记录对上 → 邀请 viewer → viewer 调用被拒 → 烧穿余额 → 402 带 topup_url → 模拟 Stripe webhook 入账 → 再调用成功 | 单条测试函数只走 HTTP：注册即登录（跨身份/治理/钱三域的编排）、凭证阶梯、402 自救合同、webhook 入账唯一性——重构期间“用户视角什么都没变”的单条证明 |
